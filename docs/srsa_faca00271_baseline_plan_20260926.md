# SRSA 作为 FACA 00271 十任务 baseline 的实验计划

## 1. 研究问题与方法名称

目标是在同一组十个装配任务上，比较 FACA 十任务共享策略、AutoMate 从零训练专家和 SRSA 检索后适应专家。SRSA 的主要结果使用论文的技能库流程：检索已有策略，以其 actor 初始化目标策略，使用 PPO + SIL 适应，完成后把目标策略加入技能库。现有十任务队列没有检索、迁移初始化或 SIL，方法名称应为 `AutoMate scratch specialists`；保留现有日志路径，只在报告中更正名称。

本地可执行的是 **SRSA 小技能库复现**：目前 `checkpoints/` 只有 `00141、00211、00426、00638、00783` 五个源策略，未发现几何编码器 checkpoint。论文的持续学习实验以十个初始策略开始；技能库少于 40 个时按几何嵌入最近邻检索，达到 40 个后才训练迁移成功率预测器。因此五源策略阶段使用几何检索，不把仓库默认的完整预测器 `embedding/train.py` 直接用于这十个任务，也不声称与论文的十源起点完全一致。

参考：[SRSA 论文 §4.2–4.3、附录 A.5.3](https://arxiv.org/html/2503.04538v1)、仓库 `README.md` 的 Skill Retrieval / Skill Adaptation 段落。

## 2. 冻结任务、环境和信息边界

- 固定 **历史 00271 版本**顺序：`00062 00186 00256 00271 00726 01079 01029 01092 01102 01125`。FACA 后续 tasksize10-v2/v2.1 替换了部分 ID，属于另一实验，不能混用。
- 初始技能库只允许上述五个外部源策略。十个目标任务不得以目标专家权重或含目标成功标签的迁移矩阵进入初始库。目标 mesh 可作为无标签几何编码器训练/检索输入；论文的几何编码器本来就使用全任务 mesh。记录 mesh 清单、哈希和是否包含目标 mesh。
- 不直接复用 `embedding/task_file.py` 的默认划分：其中六个目标任务列在 `SOURCE_TASKS`，另四个在 `TEST_TASKS`；按默认划分训练预测器会污染本实验的先验库或迁移标签。
- 仿真固定原生目标资产、`physical_grasp`、nominal geometry；关闭轴向参数采样、几何缩放、NEWT 观测、额外力观测。固定 reset、噪声、控制器、episode 上限、动作和观测维度，保存生效配置及代码哈希。源策略与目标环境必须通过观测维度、action 维度、normalizer 和加载模式检查。
- SRSA / AutoMate 专家使用原生 6D 环境动作，FACA M0 是 3D 策略动作映射到 6D 环境接口。最终可作系统级成功率对比，但不能把差异全归因于学习算法。报告列明观测、动作、先验数据和参数量。

## 3. 技能检索与扩展

1. **源库审计**：给五个 `.pth` 计算 SHA256；分别在自身任务上检查加载、确定性回合、normalizer 和动作分布。checkpoint 保存的 `frame` 合计为 22,441,984（分别为 1,708,032 / 5,885,952 / 6,111,232 / 4,890,624 / 3,846,144）；这能提供已记录的源策略环境步数，但不涵盖源策略试错、评估或几何编码成本。无法追溯的额外成本标为未知，而非零。
2. **几何表示**：用 `source/SRSA/SRSA/embedding/geometry/train.py` 训练 PointNet 几何编码器，并固定 mesh 坐标系、采样点数 2000、随机种子、模型哈希。论文使用 plug、socket、组装体特征；实现最近邻脚本时要核对这三个输入，不能把输出 JSON 中不明顺序的向量直接当距离。检索距离和 tie-break 规则在训练前冻结。
3. **零样本检索**：在当前技能库中，对每个目标任务取几何距离最近的一个源策略。保存完整排序、距离、源 checkpoint 哈希。零样本成功率用于诊断；本阶段不依据目标测试成功率改选源策略，因为论文的小库持续学习设定用几何最近邻。
4. **十任务扩展**：每条训练 seed 链严格按固定顺序逐任务进行：从当前库检索 → 适应训练 → 独立验证选 checkpoint → 入库 → 下一个任务。即使成功率为零也保留并标为弱技能，不删除任务。不同 seed 链从相同五源库开始，各自维护技能库，目标专家不跨链共享。先完成单 seed 的两任务 pilot；正式阶段 GPU0 可跑 seed 1 的完整链，GPU1 跑 seed 2 的完整链，每进程 250 env，随后补 seed 3。这样同时使用两卡，并保留论文算法逐任务入库的依赖关系。每次检索时冻结库版本和全部 checkpoint 哈希。
5. **顺序敏感性**：正式结果至少增加一个预先指定的反向任务顺序；不能看到成功率后再排任务。每个顺序从相同五源库重新开始，绝不把另一顺序的十个目标策略作为先验。

若希望严格采用论文“十个初始策略”，需另外按预先冻结的、只使用源任务信息的规则选出五个非目标任务，训练和验收五个源专家；单独统计这部分额外成本。这是增强复现，不作为启动五源 pilot 的前置条件。

## 4. 目标任务适应与预算

主方法使用 `run_w_id.py --sparse --sil --no_sbc --checkpoint <source.pth> --load_mode actor`，采用 README 的 sparse 适应设置。以目标任务官方 sparse reward 训练，FACA relaxed 指标用于独立评估。论文也有 dense 设置，本次选择 sparse 需要明确报告。当前单 checkpoint、200-iteration 路径不会触发多候选技能示范采集；若以后启用多 checkpoint 选择或周期性采集，必须把额外环境交互计入目标任务成本。当前 dense + SBC 的从零队列适合作为独立方法对照；若要单独测迁移增益，另设相同 sparse/SIL/无 SBC 的 scratch 对照。

在用户要求的每卡 250 env 下，SIL 配置的 `horizon_length=128`，每个 PPO iteration 的常规 rollout 为 32,000 transitions。其默认 `minibatch_size=512` 不能整除 32,000；启动前需显式设为同时整除 32,000 且可被 `seq_length=128` 整除的值，例如 640，central value minibatch 同样设置兼容值。先做 2–5 iteration smoke，验证回放、SIL loss、checkpoint 恢复、GPU 内存和有效吞吐，不把 smoke 结果用于模型选择。

还需解决两个具体的运行问题：`a2c_sil_continuous.py` 的多候选采集/混合路径使用共享 `tmp.pth`，启用前须改为每 run 的独立路径；当前通用 checkpoint 序列化未见 SIL replay 保存，应补齐并验证 replay、计数器、优化器和 RNG 的恢复后再启用自动续训。源策略初始化与中断恢复必须使用不同的加载规则。

建议 pilot 固定 `seed=1`，先两任务各 25 iterations；正式扩展链每任务上限 200 iterations（仓库 SIL YAML 的默认上限），每任务常规 rollout 上限 640 万 transitions，每条十任务链 6400 万，三 seed 共 1.92 亿；另列评估与任何额外采集交互。预设验证节点约为 5、25、50、100、200 iterations；早期 checkpoint 保存频率需要由专用配置支持。只用独立验证集选 checkpoint，并保留最终 200-iteration checkpoint。论文附录报告过 1000 epochs，而当前本地 SIL YAML 为 200；比较时以实际 transitions 计，不把两种 epoch 直接等同。现有 AutoMate 队列是 250×32×1500=1200 万常规 rollout transitions/任务。FACA historical joint10 M0 的总训练预算为 1,398,600 transitions，平均每任务 139,860；因此同时报告目标数据量–成功率曲线、各方法预设预算终点、源库预训练成本。FACA 预算附近只对应少数几个 SIL rollout，需额外保存早期 checkpoint，并按实际步数标注预算取整差异。

第一轮若任一方法因 200-iteration 上限尚在持续改善，可在冻结规则下延长所有十任务的统一预算，并另报追加成本；不只为单个失败任务追加预算后与原预算成绩混算。正式统计至少采用三个**完整扩展链**训练 seed，每条链各自维护技能库，不能仅把两个测试环境 seed 当作训练复现。

## 5. 评测与比较

- 主指标：FACA `relaxed_success_stable`，仅把深度条件改成 `depth_fraction > 0.85`、无上限；其余保留横向误差、无 jam、连续 3 步。姿态、yaw、keypoint 为诊断项，不进入 relaxed gate。副指标为官方锁存成功、终态深度、横向误差、jam 率。必须在同一个冻结 evaluator 上重评所有方法。
- checkpoint 验证建议 seeds `4101/4102`，每任务每 seed 100 个回合。历史可比评估继续使用 `5101/5102 × 100`；其中六任务从零训练结果已经被观察，不能再称为全新未见测试。正式论文确认结果另外冻结 `6101/6102 × 100`，在方法和模型选择规则冻结后统一重评全部方法。使用确定性策略动作、`physical_grasp`、不因中途成功提前终止；保存实际 reset 参数，不能仅凭同一个整数 seed 声称不同并行环境实现的初态逐回合一致。
- 每任务报告成功次数 `k/200`、Wilson 95% 区间；十任务报告宏平均和最差任务。训练 seed 之间报告均值与离散程度；按实际 transitions 绘制成功率曲线，并列出首次达到预设成功率阈值的交互量。
- 主表至少三行：FACA historical 00271 十任务共享策略、AutoMate scratch 十专家、SRSA 小技能库几何检索 + PPO/SIL 十专家。另附 `number_of_policies`、参数/磁盘成本、先验技能库来源与成本、目标任务总交互量。SRSA/AutoMate 与 FACA 动作和输入权限不同，主表定位为系统比较；如要归因某个设计，还需额外匹配动作与训练数据。
- 对 SRSA 做最小诊断：初始源策略零样本、适应前后；代表性弱任务的无 SIL 或无迁移对照；检索源错误/成功率和性能变化。诊断不得用最终测试集来改动主实验。

## 6. 实施顺序与交付

1. **P0 协议审计**：冻结任务、源库、环境、训练/验证/测试 seeds、成功率函数，核查现有从零训练队列的完成状态与十任务统一重评脚本。产出 `protocol.json` 和源库 manifest。
2. **P1 检索实现**：训练/加载几何编码器，新增几何最近邻脚本与检索 manifest；先对 `00062 → 00186` 做顺序 pilot，检查从初始库到扩展库的切换。pilot 不进入正式统计；正式链重新从冻结的初始五源库启动，pilot 交互作为开发成本另计。
3. **P2 正式扩展链**：两卡分别运行独立 seed 链，每进程 250 env、每链十任务顺序推进；每完成一个任务便原子更新本链的库 manifest，技术故障保留现场，低成功率如实入表。产出逐任务 learning curves、逐次库版本和日志。
4. **P3 独立评估**：将现有仅评六任务的 `scripts/run_srsa_specialist_relaxed_eval.py` 泛化为十任务、任意方法 checkpoint 的只读 evaluator；统一评估并生成逐回合数据、宏平均、失败原因表。
5. **P4 复现与扩展**：增加完整链 seed 和反向顺序；如需论文十源起点，训练额外五个非目标源任务并另列源库成本。

当前从零训练队列继续完成，日志不重写；正式结果的标题与 manifest 方法字段要更正为 AutoMate scratch。新的 SRSA 训练必须使用独立目录与锁，避免覆盖现有实验。
